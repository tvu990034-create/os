# RouterOS Repository Architecture

## Overview

RouterOS is a modular router operating system built on OpenWrt and Linux. The repository is organized to support multi-platform firmware generation while maintaining a shared codebase for router functionality.

## Directory Structure

```
router-os-source/
├── custom-feed/              # Custom OpenWrt packages
│   ├── router-core/         # Core system services and utilities
│   ├── router-net/          # Network monitoring and health
│   ├── router-ui/           # LuCI management interface
│   ├── router-tests/        # On-device tests
│   ├── router-dsa-sdk/      # DSA algorithm SDK (future work)
│   └── router-dsa-runtime/  # DSA runtime (future work)
├── custom/                  # Custom configuration overlays
│   └── overlay/             # Board-independent service defaults
├── config/                  # Build configurations
│   ├── platforms.tsv        # Platform registry
│   ├── x86_64.config        # x86_64 firmware config
│   ├── armsr_armv8.config   # ARMv8 firmware config
│   └── sdk-*.config         # SDK package build configs
├── scripts/                 # Build and validation scripts
│   ├── build-platform.sh    # Platform firmware build entry point
│   ├── validate-*.py        # Validation scripts
│   └── install-build-deps-ubuntu.sh
├── tests/                   # Host-side tests
│   ├── router-core/         # Core package tests
│   ├── dsa-sdk/             # DSA SDK tests
│   └── setup/               # Setup tests
├── docs/                    # Documentation
│   ├── architecture/        # System architecture
│   ├── development/         # Development guides
│   ├── platforms/           # Platform documentation
│   ├── user-guide/          # User documentation
│   ├── operations/          # Operations documentation
│   └── reports/             # Historical audit reports
├── openwrt/                 # OpenWrt source (gitignored)
└── .github/workflows/       # CI/CD workflows
```

## Custom Feed Packages

### router-core
**Purpose**: Core system services and utilities

**Responsibilities**:
- First-boot configuration defaults
- Security defaults
- Hardware inventory
- System status reporting
- Configuration backup/restore
- Safe shutdown/reboot
- WAN/LAN configuration helpers
- Firmware upgrade helpers
- Service supervision
- Logging configuration

**Installation Paths**:
- `/etc/uci-defaults/`: First-boot scripts
- `/etc/init.d/`: Init scripts
- `/etc/hotplug.d/`: Hotplug handlers
- `/usr/libexec/router-core/`: Executable utilities

### router-net
**Purpose**: Network monitoring and health

**Responsibilities**:
- Network interface observation
- Network health monitoring
- Interface state tracking

**Installation Paths**:
- `/etc/config/`: Configuration
- `/etc/init.d/`: Init script
- `/usr/libexec/router-net/`: Executable utilities

### router-ui
**Purpose**: LuCI management interface

**Responsibilities**:
- System overview dashboard
- Read-only status display
- Configuration stubs (to be expanded)

**Installation Paths**:
- `/www/luci-static/resources/view/routeros/`: LuCI views

### router-tests
**Purpose**: On-device smoke tests

**Responsibilities**:
- Configuration syntax validation
- Hardware detection tests
- Network validation tests
- Connectivity tests

**Installation Paths**:
- `/usr/libexec/router-tests/`: Test scripts

### router-dsa-sdk (Future Work)
**Purpose**: DSA algorithm development SDK

**Responsibilities**:
- C ABI headers for plugins
- Plugin development tools

**Status**: Deferred until router OS is complete

### router-dsa-runtime (Future Work)
**Purpose**: DSA plugin runtime

**Responsibilities**:
- Plugin loader
- Offline test runner

**Status**: Deferred until router OS is complete

## Configuration Overlays

### custom/overlay
Contains board-independent service defaults:
- `etc/config/firewall`: Default firewall rules
- `etc/config/dhcp`: Default DHCP configuration

**Important**: Network and system configuration are generated by OpenWrt for each board. These overlays only contain services that are independent of board topology.

## Platform Registry

### config/platforms.tsv
Registered platform profiles with fields:
- `profile`: Profile identifier
- `type`: Platform type (generic-pc, generic-arm64, generic-vm, board-specific)
- `target`: OpenWrt target
- `subtarget`: OpenWrt subtarget
- `config file`: Path to configuration file
- `status`: development, experimental, verified, production-ready

## Build Scripts

### scripts/build-platform.sh
Entry point for building firmware for a registered profile.

**Features**:
- Validates profile against registry
- Runs setup.sh to prepare OpenWrt tree
- Updates and installs feeds
- Applies profile configuration
- Builds firmware
- Verifies output

### setup.sh
Prepares the OpenWrt build tree.

**Features**:
- Clones pinned OpenWrt version
- Registers custom feed
- Syncs service overlays
- Preserves board-generated network/system config
- Validates OpenWrt ref

## Validation Scripts

### validate-packages.sh
Main source validation entry point.

**Checks**:
- Package Makefile structure
- SDK configuration selects required packages
- Shell syntax for all scripts
- Platform profile validation
- UCI configuration syntax
- LuCI JavaScript syntax
- Package file existence
- Overlay synchronization tests
- First-boot network tests

### scripts/validate-platforms.py
Validates platform registry entries.

**Checks**:
- Profile naming conventions
- Duplicate profiles
- Target/subtarget validity
- Status validity
- Type validity
- Configuration file existence
- Target selectors in config
- Device profile selection
- Required package selection

### scripts/validate-uci.py
Validates UCI configuration syntax.

### scripts/validate-ui.py
Validates LuCI UI metadata and ACLs.

### scripts/validate-package-files.sh
Validates that all files referenced in Makefiles exist.

## Platform Independence

RouterOS is designed to support multiple hardware platforms:

1. **Generic x86_64 PCs**: Desktop, mini PC, workstation, server
2. **x86_64 Virtual Machines**: QEMU, VMware, VirtualBox
3. **Generic ARM64**: Arm SystemReady/EFI platforms
4. **Board-specific routers**: Using actual OpenWrt device profiles

**Key Principle**: The router OS codebase is hardware-independent wherever possible. Hardware-specific behavior is handled through:
- OpenWrt board metadata
- Platform-specific configuration
- Device profiles
- Runtime capability detection
