# RouterOS System Overview

## High-Level Architecture

RouterOS is a router operating system built on OpenWrt and Linux. It provides a complete, configurable, secure router for compatible hardware platforms.

## Design Principles

1. **Platform Independence**: The core router OS is hardware-independent. Platform-specific behavior is handled through OpenWrt's device profiles and board metadata.

2. **OpenWrt Integration**: RouterOS extends OpenWrt rather than replacing it. We use OpenWrt's networking stack, firewall, DHCP, DNS, and management components where possible.

3. **Modular Packages**: RouterOS functionality is organized into OpenWrt packages with clear responsibilities and dependencies.

4. **Board Configuration Preservation**: Network and system configuration generated by OpenWrt for each board is preserved. RouterOS only adds board-independent service defaults.

5. **Multi-Platform Support**: The system can generate firmware for different hardware targets through platform-specific configurations.

## Configuration Flow

### First Boot
1. OpenWrt generates network/system config from board metadata
2. RouterOS UCI defaults apply security and service defaults
3. RouterOS first-boot wizard prompts for initial configuration
4. System boots with appropriate defaults

### Runtime Configuration
1. User configures through LuCI or CLI
2. UCI configuration files are updated
3. Services reload configuration
4. Changes take effect immediately

### Configuration Persistence
1. UCI configurations persist across reboots
2. Backup files stored in `/etc/routeros-backups/`
3. Backup/restore tools preserve full configuration
4. Firmware upgrades preserve configuration by default

## Platform Support Model

### Supported Platforms
- **Generic x86_64 PCs**: Intel/AMD desktop, mini PC, workstation, server
- **x86_64 Virtual Machines**: QEMU, VMware, VirtualBox
- **Generic ARM64**: Arm SystemReady/EFI compatible platforms
- **Board-specific routers**: Using actual OpenWrt device profiles

### Platform Profile Structure
Each platform profile specifies:
- OpenWrt target and subtarget
- Device profile
- Package selection
- Configuration defaults
- Validation status

### Platform Validation
Platforms are validated at multiple levels:
- Source-level: Configuration files and dependencies
- Build-level: SDK package compilation
- Firmware-level: Complete firmware build
- Runtime-level: QEMU boot and networking
- Hardware-level: Physical device testing

## Security Model

### Default Security
- SSH requires key-based authentication (password auth disabled)
- Web management restricted to LAN address
- Firewall configured with reasonable defaults
- Root password required for remote administration

### Security Layers
1. **Authentication**: SSH keys, root password
2. **Authorization**: RPC ACLs, LuCI permissions
3. **Network Security**: Firewall zones, NAT, port filtering
4. **System Security**: Service supervision, logging, monitoring

## Upgrade and Recovery

### Firmware Upgrade Process
1. Verify firmware file format and size
2. Check available storage space
3. Create configuration backup
4. Stop critical services
5. Apply firmware using OpenWrt sysupgrade
6. Reboot and verify services

### Recovery
- Configuration backup/restore
- Rollback support (through OpenWrt mechanisms)
- Recovery mode on boot failure
- Safe upgrade validation

## Dependencies on OpenWrt

RouterOS depends on the following OpenWrt components:
- **procd**: Process manager
- **netifd**: Network configuration daemon
- **firewall4/nftables**: Firewall management
- **dnsmasq**: DHCP and DNS server
- **odhcpd**: IPv6 DHCP
- **uhttpd**: Web server
- **rpcd**: RPC daemon
- **uci**: Configuration management
- **ubus**: System bus

RouterOS extends these components but does not replace them.
